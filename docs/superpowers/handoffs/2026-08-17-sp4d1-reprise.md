## The tool that survives this wave

`frontend/maquette/fidelity.py` — run BY HAND while a page is being converted, against the
legacy renderer, BEFORE deleting it:

```
python3 frontend/maquette/fidelity.py viewSystemLegacy systeme systeme-panne …
```

It needs the legacy renderer reachable as `window.__referentiel.<name>`, added for the proof and
removed with the renderer. It normalises the three things that are the WRITER and not the
markup — inline-style serialisation, attribute ORDER, whitespace runs — and each of those cost a
full measuring cycle to understand. It deliberately does NOT normalise a whitespace text node
between TEXT and a tag: that one renders.

## Rulings made this wave (all contestable)

- **The page host portals into the legacy `#view`, and the host element IS the page's root**
  (`div.body`, which all three pages emit) rather than a wrapper. The alternative — a container
  of the shell's own, outside `#view` — moves the markup out of `.stage`'s layout context and
  forces a CSS amendment the spec reserves for SP5, and every harness selector reading `#view …`
  would have to move with it.
- **The shell empties `#view` when it takes ownership**, once, on the transition. Not on every
  render, and not in the legacy, which cannot know when React is ready to draw. Handing back
  needs nothing: the legacy's own `innerHTML` write removes what React left.
- **Why a host element rather than portalling straight into `#view`**: leaving a migrated page,
  the legacy's write runs FIRST (synchronously, from `applyState`) and React unmounts after, so
  React would be removing children that are already detached. With a host, React only ever
  touches children of a node it owns, attached or not.
- **`REG_ETAT` stays the fragment's**, read by the component through the store's `version` bump.
  R60 reads `REG_ETAT.modifs` in five holds; making it React-owned leaves them with nothing.
- **Shared emitters are reused VERBATIM, and split rather than re-derived**: `listeFaitsHTML`
  gained `lignesFaitsHTML`, `skelCards` gained `skelCardsInner`, `surfErr` gained `surfErrInner`,
  `emptyHTML` gained `emptyInner` — each outer function emits exactly what it always did, and the
  inner one exists because React cannot set the outer markup of a node it also draws.
- **A migrated page's `PAGES_OF` entry loses its `render`.** Clearing `shellOwned` without
  restoring a renderer then CRASHES, rather than silently drawing a page nobody maintains.
- `Icon` extracted on its THIRD user (`components/icon.tsx`), which is what `add.tsx`'s own
  comment said would be the signal. The two existing copies were byte-identical, checked first.

## The traps this wave paid for

1. **A guard that asserts an EMPTY set passes on a dead detector.** R60's « every setting subject
   carries a written name » reads `window.__sujetsSansNom`, filled as a SIDE EFFECT of naming a
   subject. Deleting that side effect — exactly what `panel.tsx` did — leaves the hold GREEN.
   Proven by mutation. The fix is a POSITIVE CONTROL: a probe segment no table can name must be
   CAUGHT before the emptiness means anything. **Any hold that asserts an absence needs one.**
2. **A rule can drive a page without ever touching its controls.** R67 reaches Maintenance
   through `applyState`, never through a tap, so no rule guarded `data-maintrub` /
   `data-maintact` — a component that stopped emitting one would break the page with every rule
   green. The wave that MOVES an emitter owes its attributes a hold, driven by a real tap.
3. **A hold that clicks blind CRASHES instead of failing.** The first version of that hold timed
   the click out when the attribute was gone, which reads as a broken rule rather than a named
   defect. Look the element up, then assert.
4. **Three classes of oracle noise, all of them the writer** — see `fidelity.py`'s docstring.
   Chasing them as defects wastes a cycle each.
5. **Whitespace text nodes between TEXT and a tag are real.** `{" "}` where the legacy template
   broke a line inside an inline container. This wave restored two (the label and its origin, the
   sentence and its button); SP4b paid it three times.
6. **`git` haste costs more than it saves.** A `&&` that did not guard the following line let a
   commit through whose message described only half its content (reverted with `reset --soft`,
   nothing lost, redone). A reflex `git stash --keep-index` created a redundant stash that had to
   be verified empty before dropping. Neither was necessary; both were cheap only because they
   were checked.
