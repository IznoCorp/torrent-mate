# L01 — the recorded oracle

> Lot **L01** of `docs/reference/frontend-architecture.md` (BINDING) — Phase 0, the safety net.
> `runs alone`. Serves `docs/reference/product-intent.md` **§15** (the maquette is the visual
> reference; it is modified first and verified with its harness).
>
> **Phase 0 says « Nothing else may start. »** Every lot after this one changes mechanism while
> promising the rendering is unchanged, and that promise is unprovable today.

## Why this lot exists, and why it is first

`fidelity.py` cannot run. Its own docstring planned for this — « it stops being runnable the
moment the legacy renderer it compares against is deleted. That order is the point: prove first,
delete after. » The renderers are gone, no recording is committed, and 38 of the 82 state ids
were renamed across #455 and #456. `scripts/parity-probe.py` went with the translation layer in
#465, correctly: it served the abandoned surface-by-surface model.

So the repository has **no way to say whether the maquette still renders what it rendered
yesterday**. L02 moves 280 test anchors, L06 folds every declaration onto a scale, L07 replaces a
4 043-line stylesheet with utilities — each promises the rendering is unchanged, and none of them
can currently prove it.

## What it is, in one sentence

One command that says whether the maquette renders today what it rendered at a known-good commit.

## What it measures

Per *(named state × region)*: the **bounding rectangle**, plus a fixed subset of **computed style
properties**. Never a screenshot — D8, and it is measured rather than believed: two captures of
the same unmodified file diverge on 8 to 15 states, and one run of a screenshot oracle once
« proved » twenty states had changed after a deletion that was correct all along.

### The states are the 82, and they are obtained by EXECUTING `states.js`

Never by regex. 74 entries are written out and 8 are generated by a `...[…].map()` (the eight
`settings-field-*` states), so a pattern match reads 74 — and an adversarial review has already
declared the figure 82 wrong on exactly that mistake. `window.__recordStates` receives 82, with
82 unique ids.

**Not the 49 states of the retired probe.** Two inventories coexisted and they never counted the
same thing: 82 = the states `states.js` registers; 49 = the named states `regions.json` drove for
the extraction contract. The oracle takes the source, not the subset.

## Its shape — three modes

| Mode | What it does |
| ---- | ------------ |
| `--record` | writes the reference |
| `--check`  | compares against the reference; **exits non-zero** on any divergence, naming the state, the region, the property and its before/after |
| `--accept` | entérines a reviewed change into the reference |

**The reference is a committed JSON**, stably sorted and formatted, one entry per
*(state, region)*. That is the point of its shape and not an implementation detail: **a visual
change is then read in the pull request's diff**, region by region, instead of arriving as an
opaque verdict. A reviewer sees `font-size: 12px → 13px` on `library/card` in the diff.

The reference records the **known-good commit it was taken at** — `3e275aad`, today's `main`,
where the prototype is stable and its 50 rules are green. « Known-good » with no SHA means
nothing.

## The measurement recipe is RECOVERED, never reinvented

`regions.json`'s `probe` block held the only replayable measurement recipe this repository ever
proved. #465 removed it with the rest of the translation layer. It comes back from history:

```bash
git show bd31d52b:frontend/maquette/regions.json   # the commit before the untranslate merge
```

Its six keys come back with a comment saying where they came from — **rebuilding the list by
judgement re-opens a question already settled by measurement.**

| Key | Recovered as | Why |
| --- | ------------ | --- |
| `viewport` | as-is — 390 × 844, DPR 2, `isMobile`, `hasTouch` | a geometry read at another width answers a question nobody asked |
| `assertBeforeMeasuring` | as-is — `document.documentElement.clientWidth === 390` | refuse to measure if the viewport is not really that |
| `computedStyleSubset` | **amended — 17 → 19 properties**, see below | `position` `font-size` `font-weight` `line-height` `padding` `margin` `border` `border-radius` `gap` **`opacity`** **`visibility`** `color` `background-color` `box-shadow` `animation` `display` `flex-direction` `align-items` `justify-content` |
| `knownAbsent` | as-is — 3 entries | each names a region an INTERACTION gates, which state-driving cannot reach; each carries its reason |
| `neutralise` | as-is — `.note` | prototype-only chrome, removed from the DOM before measuring. Left in place it springs back to 75.6px and pushes every region below it down — a probe measuring its own setup |
| `allowlist` | **EMPTY, and that is the one correction** | its single entry (`.bottombar`, `position: absolute` vs `fixed`) described a **maquette-vs-app** divergence — the model #465 abandoned. Here both sides are the maquette at two commits, so the entry has no subject. Recovering it would seed the allowlist with a justification for a comparison this oracle never makes. |

### The one amendment, and it carries its measurement

`computedStyleSubset` gains **`opacity` and `visibility`** — 17 properties become 19.

**Why the recovered list is short here, and it is not a criticism of it.** It was assembled for a
comparison where both sides sat in the SAME interaction state: the maquette against its own CSS
extraction. This oracle compares the maquette against ITSELF at two commits, across 82 states
that OPEN AND CLOSE LAYERS — a question the old list never had to answer.

**Measured, not argued.** Between `lib-list` and `drawer-navigation`:

| Region | 17 properties identical? | Bounding rect identical? | Verdict |
| ------ | ------------------------ | ------------------------ | ------- |
| `#scrim`  | 17/17 | **yes** | **BLIND** — only `opacity` and `visibility` move |
| `#sheet`  | 17/17 | no — `transform` moves it | seen, by the rectangle |
| `#screen` | 17/17 | **yes** | **BLIND**, and `opacity`/`visibility` do not help either |

So the overlay could stop appearing altogether and the instrument would stay green. With 19
properties the same comparison reports `['opacity', 'visibility']` — the hole is closed, verified
by re-running it.

`#screen` is a second lesson rather than a second amendment: **a region is declared on a layer's
CONTENT, never on the layer host.** Nothing about `#screen` itself changes when a screen opens;
its children change. Phase 2 declares regions accordingly.

**This is an ADDITION carrying evidence, not the rebuild-by-judgement L01 forbids** — that
prohibition targets re-deriving the list from taste, which is what produced a wrong list before.
Per § 7 of the architecture file the operator arbitrates; this is flagged in the pull request
rather than assumed, and reverting two entries costs nothing if the arbitration goes the other
way.

## The regions are RE-DECLARED, and anchored on `data-*`

The architecture file is explicit: « Regions are re-declared for this purpose: one region per
block a user perceives as a unit. The 51 regions of the retired probe were chosen for the
extraction contract and are not automatically the right list. »

They were also anchored on **CSS classes** — `.viewtabs`, `.seg`, `.strip`, `.crossref` — and
each was pinned to a single state.

**Recovering them as-is would break the oracle at the exact moment it is needed, and the reason
is circular:** this oracle exists to prove **L07** changed no rendering. L07 replaces
hand-written classes with Tailwind utilities. A region anchored on `.strip` disappears when that
surface converts — so the instrument loses its target precisely when it is supposed to be
watching. The same argument is D4's, one level up: a rule anchored on a style class fails when
the STYLE changes, which is the opposite of what a rule is for.

So: **`data-*` attributes and structural ids, never a class.** Where no anchor exists, one is
added — `data-region="<page>/<part>"` — and its **three ends move in the same commit**: the
markup that emits it, `regions.json` that declares it, and the oracle that reads it. That third
end is what satisfies `scripts/check-markup-contracts.py`, which refuses a `data-*` value the
markup emits and no reader understands.

The 51 old regions are read as a **corpus of what was worth measuring**, not as a list to import:
their keys (`acquisition/card`, `suivis/filters`, …) name blocks that are still blocks.

## What it does NOT do

It is not a functional test. `frontend/maquette/harness/run.sh` is, and it already runs itself in
two tiers — `--contracts` (minutes, on every PR) and the full suite (20-25 minutes, the gate
before a wave merges).

**The oracle is a THIRD tier and duplicates neither**: the rules say the behaviour still holds,
the oracle says the rendering did not move. It is too slow for `make check` and belongs to the
wave gate.

## Friction is the risk, and each counter-measure is EXERCISED

« Exercised rather than asserted » is the architecture file's wording and it is the bulk of this
lot. A counter-measure that is merely coded is a claim; one that is demonstrated failing without
it is a proof.

| # | Cause | Counter-measure | How it is exercised |
| - | ----- | --------------- | ------------------- |
| 1 | animations, async image decode | animations off, reduced motion forced, images decoded before measuring, and an **explicit settle signal** — never a delay in milliseconds | disable the settle signal, show the oracle reporting divergence on an unmodified tree, restore |
| 2 | non-deterministic data | frozen clock, frozen fixtures | a rule has ALREADY failed here because a scheduler fired (R63). Unfreeze the clock, show a state diverging, restore |
| 3 | slowness | one browser, one context, states driven **in-page** | measured: report the wall-clock for a full run, and show that a per-state browser launch is materially slower |
| 4 | unreadable diffs | sorted JSON; report grouped by state, naming the property and its before/after | shuffle the key order on write, show the diff becoming unreadable, restore |
| 5 | false positives, which disarm an oracle within weeks | an allowlist, each entry carrying its **written reason** | an entry with no reason is refused, mutation-tested |

## Two notes carried forward, so later lots do not catch it out

1. **When real data replaces the fixtures (L09), determinism moves to the mock layer** — the
   oracle then depends on **L08**. Planned together, not against each other.
2. **Once L12 lands view transitions**, a transition in flight moves the very rectangles this
   measures. The oracle reads **at rest**, and its settle signal must GUARANTEE that rather than
   assume it.

## Out of scope, said explicitly

- **L02** (moving the 280 class-anchored rule selections) — a separate lot that depends on this
  one. This lot adds `data-region` anchors for the ORACLE only; it does not re-anchor the rules.
- Any visual change. This lot measures; it changes no rendering. That is what makes its own
  reference trustworthy.
- `fidelity.py` — left in place, unchanged. It measured MARKUP and did its job; this oracle
  measures geometry and computed style. They do not overlap and neither replaces the other.

## ACCEPTANCE

Every criterion is an executable command with its expected output, per
`docs/reference/feature-lifecycle.md`. **Every one below was RUN**, and the expected outputs are
what it printed — not what it was meant to print. Two were rewritten because the first version
could not have proved what it claimed; both rewrites are named.

Each browser criterion assumes the prototype is built and copied where the harness reads it.
`frontend/maquette/harness/run.sh` does that itself; run it by hand otherwise:

```bash
cd frontend/maquette/design && npm run build \
  && cp dist/index.html /tmp/tm-refonte/wrapped.html \
  && rm -rf /tmp/tm-refonte/vite && cp -R dist/vite /tmp/tm-refonte/vite
```

**ACC-01 — it runs in one command and is green against its own reference**

```bash
python3 frontend/maquette/oracle.py --check; echo "exit=$?"
```
Expected: `82 states x 33 regions, 2706 measurements in ~24s`, then `no divergence`, `exit=0`.

**ACC-02 — it drives 82 states, counted by EXECUTION**

```bash
python3 -c "
import json; d=json.load(open('frontend/maquette/oracle-reference.json'))
print(d['counts'])"
```
Expected: `{'states': 82, 'regions': 33}`. The count comes from `window.__states()`, never from a
regex over `states.js`: 74 entries are written out and 8 generated by a `.map()`, and an
adversarial review has already called the figure 82 wrong on exactly that mistake.

> **Rewritten.** The first version called `--check --summary-json`, a flag that does not exist.
> It would have failed on its own argument parser while appearing to test the state count.

**ACC-03 — it fails on a deliberate ONE-PIXEL padding change, and names the right region**

```bash
F=frontend/maquette/design/refonte.html; cp "$F" /tmp/l01-acc03.bak
python3 -c "
import pathlib
p=pathlib.Path('$F'); t=p.read_text()
old='padding: 11px 12px;'
assert t.count(old)==5, f'{t.count(old)} occurrences — mutation ABANDONED'
p.write_text(t.replace(old,'padding: 12px 12px;',1))"
(cd frontend/maquette/design && npm run build >/dev/null \
  && cp dist/index.html /tmp/tm-refonte/wrapped.html)
python3 frontend/maquette/oracle.py --check; echo "exit=$?"
cp /tmp/l01-acc03.bak "$F"
(cd frontend/maquette/design && npm run build >/dev/null \
  && cp dist/index.html /tmp/tm-refonte/wrapped.html)
```
Expected: `exit=1`, `10 divergence(s)`, every one on `shell/sheet-content`, each a height of
`+2px` (one pixel at the top and one at the bottom of the mutated rule), across the ten
`settings-*` states that open the panel. **This is the architecture file's own « Done when » for
this lot.**

The anchor is `padding: 11px 12px;` because it EXISTS — five occurrences, first one mutated,
verified with `grep -c`. An earlier draft anchored on `padding: 12px 14px;`, which is in no
version of the file: the assert would have fired and the criterion would have proved nothing.

**ACC-09 — an allowlist entry with no written reason is refused**

```bash

**ACC-10 — friction 1: without the settle signal, an unmodified tree diverges**

```
Expected: `exit=1`, **45 divergence(s)** on a tree that is otherwise unchanged. The

**ACC-11 — friction 2: the clock is fixed, and NOTHING NEEDED IT**

```bash
TM_ORACLE_NO_FROZEN_CLOCK=1 python3 frontend/maquette/oracle.py --check; echo "exit=$?"
```
Expected: `no divergence`, `exit=0`.

> **This criterion asserts the opposite of what it was written to assert, and that is the
> finding.** It was drafted expecting `exit=1`. Measured, the clock changes nothing this oracle
> can see: sweeping all 82 states at 03:00 and again at 23:30 produced zero divergent
> `(state, region)` pairs. The reason is structural — the instrument measures geometry and
> computed style, never TEXT, so « Prochaine recherche à 3 h 20 » changing says nothing until it
> wraps a line. The clock stays fixed because it costs one line and is the difference between
> « no dependency today » and « no dependency ». Writing down a demonstration that did not
> happen would have been worse than having none.

**ACC-12 — friction 4: an unsorted reference buries the change**

```bash
TM_ORACLE_UNSORTED=1 python3 frontend/maquette/oracle.py --record --stdout > /tmp/unsorted.json
diff /tmp/unsorted.json frontend/maquette/oracle-reference.json | wc -l
```
Expected: **7083** lines of difference on an unchanged tree — against `0` for the sorted path
(ACC-04). That is the failure sorting prevents, and it is why the sort is explicit rather than
inherited from a dict's insertion order.
